# 传统小型无纺布企业官网设计说明

## 1. 项目目标

为一家传统小型无纺布生产企业制作中文静态官网。网站帮助采购人员快速确认企业主体、主营产品、生产条件、质量控制方式、适用场景和联系方式，同时为搜索引擎与生成式搜索提供清晰、可验证、可引用的页面结构。

网站参考 `jinseed-geo.com.cn` 的制造企业信息组织方式，但不复制其品牌、文案、数据或资产。视觉与表述主动降低“大型集团、科研龙头、全球领先”等不适合小企业的暗示。

## 2. 设计方向

采用“朴素工业型”方案：

- 主色为深绿色，背景使用暖灰与纸张白，少量黄铜色作为提示色。
- 版式以清晰的大标题、直角或小圆角卡片、细边框、参数表和证据型内容为主。
- 图片位置用于企业后续替换真实厂房、设备、检测过程与产品照片；演示阶段不使用会暗示企业规模或资质的虚假照片。
- 动效保持克制，仅使用导航展开、轻微悬停和进入视口淡入，不营造过度科技感。
- 桌面端强调完整信息与横向参数，移动端强调顺序阅读、拨号和咨询入口。

## 3. 信息架构

网站采用 10 个主要栏目，并保留独立、稳定、语义明确的 URL：

1. `/` 企业首页
2. `/about/` 企业介绍
3. `/factory/` 工厂实力
4. `/equipment/` 生产设备
5. `/quality/` 质量检测
6. `/products/product-a/` 产品 A
7. `/products/product-b/` 产品 B
8. `/products/product-c/` 产品 C
9. `/applications/` 应用场景
10. `/knowledge/` FAQ / 知识库

知识库包含一个可复用的文章详情模板与至少一篇占位示例文章，用于验证 Article 结构化数据和后续内容扩展。网站另设轻量联系区块，不新增虚构的客户案例、认证荣誉或新闻栏目。

## 4. 首页结构

首页按采购决策顺序组织：

1. 顶部联系信息条与主导航
2. 企业定位与主营产品概述
3. 三个产品入口
4. “我们能提供什么”事实型能力说明
5. 工厂、设备、质量三类证据入口
6. 主要应用场景
7. 常见采购问题
8. 联系行动区与页脚主体信息

首页不展示未经确认的产能、厂房面积、员工数量、出口国家、客户数量、合作品牌、认证、专利或检测结论。

## 5. 页面内容边界

### 企业介绍

展示企业法定名称、品牌简称、成立时间、注册地址、工厂地址、主营范围和企业简介。缺失值直接显示可搜索的占位格式，如 `[待企业确认：企业法定名称]`。

### 工厂实力

展示厂房环境、生产流程、原料管理、仓储与发货等可由真实照片和文字证明的内容。不给出未确认的规模数字。

### 生产设备

按设备卡片展示设备名称、用途、适用产品和现场照片。设备型号、数量和自动化程度均为待确认字段。

### 质量检测

展示来料检查、过程检查、成品检查和留样/记录的通用流程。具体检测项目、执行标准、检测设备、频次和结果必须由企业确认后填写。

### 产品页

每个产品页包含：产品名称、定义、材料、工艺、规格参数、特点、应用、包装交付、可定制项、采购前需确认事项和咨询入口。产品名称与全部参数默认使用明确占位符。

### 应用页

按应用需求而非夸张行业覆盖展示场景。每个场景说明关注指标、可选产品及询价前需要提供的信息。

### FAQ / 知识库

FAQ 回答 MOQ、规格、打样、交期、包装、运输和定制等采购问题，但所有企业特定答案均保留待确认字段。知识文章使用可引用的标题、摘要、发布日期、更新时间、正文层级和相关文章。

## 6. 组件与数据边界

- `SiteHeader`：桌面导航、移动菜单和当前页面状态。
- `SiteFooter`：企业主体、地址、电话、邮箱、备案号占位及快捷导航。
- `PageHero`：栏目标题、摘要、面包屑和可选图片位。
- `EvidenceCard`：工厂、设备、检测等证据型条目。
- `ProductCard`：产品摘要与独立详情入口。
- `SpecTable`：语义化产品参数表。
- `PlaceholderNotice`：统一解释待确认字段，不让占位符被误认为真实数据。
- `ContactPanel`：电话、邮箱、地址和询价准备项；不提供无后端支撑的假表单提交。
- `JsonLd`：在各页面输出与内容类型匹配的结构化数据。

企业资料、联系方式、产品和应用内容集中保存在可编辑数据文件中，页面只负责展示，避免在多个页面重复修改事实。

## 7. SEO 与 GEO

- 每页具有唯一 `title`、`description`、canonical 和 Open Graph 元数据。
- 生成 `robots.txt` 与 XML sitemap。
- 使用清晰的 H1–H3 层级、语义化 HTML、可读 URL、内部链接与面包屑。
- 首页提供 Organization JSON-LD；产品页提供 Product；内页提供 BreadcrumbList；文章页提供 Article；FAQ 页面提供 FAQPage。
- 结构化数据只引用页面上实际可见的内容，不用占位数据伪造评价、报价、认证或性能结论。
- 为图片提供描述性文件名、尺寸属性与替换说明，真实图片到位后再写准确 alt 文本。
- 通过统一企业名称、地址、电话和域名字段，为后续备案域名及第三方平台实体一致性做好准备。

## 8. 技术架构与部署

- Astro 静态输出，不依赖数据库或服务器运行时。
- 内容以 TypeScript 数据模块或 Astro Content Collections 管理。
- CSS 使用项目内设计变量和组件样式，不引入重量级 UI 框架。
- 构建产物输出至 `dist/`，适配 GitHub 私有仓库和 EdgeOne Pages。
- `site` 基础地址通过 Astro 配置中的企业域名占位符统一管理，上线前替换。
- README 说明本地运行、资料替换、构建、GitHub 推送、EdgeOne 构建命令、输出目录、域名与备案注意事项。

## 9. 可访问性与错误处理

- 键盘可操作导航，移动菜单具有正确的展开状态。
- 颜色对比满足常用可读性要求，正文不依赖颜色传达信息。
- 图片提供固定尺寸，避免布局跳动；缺失真实图片时展示明确的“待替换真实照片”版块。
- 无效路径提供 404 页面和返回首页入口。
- 联系信息缺失时不生成 `tel:` 或 `mailto:` 空链接。

## 10. 验证标准

- `npm run build` 成功，Astro 无构建错误。
- 10 个主要栏目及文章示例均生成静态 HTML。
- 桌面端与 390px 移动端无横向溢出，导航可使用。
- 所有站内链接可解析，sitemap 和 robots 内容正确。
- 结构化数据可解析，且类型与页面一致。
- 全项目扫描不得出现虚构的产能、资质、客户、认证、检测数值或行业排名。
- 页面占位项格式一致，并在 README 中列出上线前必填清单。

## 11. 后续需要企业提供的资料

上线前需要：企业法定名称与简称、Logo、域名、备案号、成立时间、地址、电话、邮箱、简介、三类真实产品名称和参数、设备清单、质检流程与标准、应用范围、工厂/设备/检测/产品真实照片，以及所有可公开证明的资质文件。资料未提供前，网站保持占位状态，不对外作为正式企业信息发布。
